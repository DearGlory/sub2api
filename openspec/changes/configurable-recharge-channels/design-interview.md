### 复用与不复制

- 两边均使用现有 Go payment/provider 接口和 Vue 支付页面结构，可以借鉴 provider 和接线逻辑；不能整块覆盖目标的支付服务、充值赠送、退款或订阅文件。
- 来源 EPUSDT 的退款方法明确返回“不支持”。是否开放人工处理，以及用户界面怎样说明，需要在选定接入路线后明确。
- 目标 `backend/ent/schema/payment_provider_instance.go` 已有字符串服务商标识与配置存储。当前未证实必须新增数据库结构；不提前安排迁移编号。
- 来源 EPUSDT 的 `currency` 与付款 `token` 是不同参数。界面、回调金额核对、汇率与余额入账单位不能混同。
- 来源 `LICENSE` 为 LGPL-3.0；实施时保留来源与许可标记，本记录不代替发布合规审查。

## 第一轮决策（用户已确认）

### Q1：外部充值页的交付边界

用户选择：“可以，本次只做接入与配置”。本次接入已有外部收银台，不包含建设或部署外部收银台。页面展示不等于付款后的自动入账；身份与入账协议仍是待核实前置。

### Q2：USDT 接入路线

用户选择：“可以，采用兼容网关模式”。采用来源代码对应的 EPUSDT／GMPay 兼容网关路线，接入现有充值订单和入账链路。管理员配置网关地址和商户参数，不新建链上监听和钱包托管。具体网关的协议兼容性仍需验证。

### Q3：外部页面配置粒度

用户选择：“可以，一张综合充值页”。支付宝与微信共用一张外部充值页，不分别配置两张页面。支付设置中具体字段、身份传递与显示方式在后续轮次确认。

### Q4：与现有充值／订阅的关系

用户选择：“可以，与现有功能并存”。保留原有内置充值和订阅；外部充值页是可关闭的新增入口，USDT 是内置充值的新增支付方式。不得照搬来源项目替换订阅入口的行为。

这四项仅批准设计范围，不代表整体方案已确认或获准开始实现。

## 当前核查批次

两条独立只读核查均已返回。父助手已复核来源查单／回调／退款实现、目标查单金额校验、订单快照、迟到付款处理、外部 URL 身份透传及集成文档，并查阅 GMWalletApp/epusdt 项目第一方 API 文档。完整记录见 `payment-boundary-findings.md`。

## 第三轮决策（用户已确认）

- Q9：用户选择“可以，买卡后回 Sub2API 兑换”。外部入口采用“店铺购买 → 获得兑换码 → 返回本站兑换余额”，不通过该入口自动给当前登录用户入账，不向店铺发送本站登录 token；是否发放 Sub2API 可用的余额码仍需运营侧核对，本轮未修改店铺商品、库存或说明。
- Q10：用户选择“可以，只做适配和配置”。USDT 本次只实现 Sub2API 适配器与后台管理配置；GMwalletApp/epusdt 网关部署、维护和运行地址由独立流程负责，运行地址以后由管理员填写。

第三轮证据见 `external-shop-evidence.md`。两条入账链路保持独立：外部买卡以本站兑换成功为准；USDT 以本地订单及经核验的网关收款证据履约。外部买卡不复用 USDT 回调，不读取跨域页面来判定支付成功。

GMPay 专项核查已返回并由父助手独立复核官方固定提交的状态接口、通知结构、回调发送及路由。记录见 `gmpay-protocol-evidence.md` 和 `settlement-policy-review.md`。公开状态查询缺少目标履约所需金额；合法签名成功通知可提供订单、商户和金额证据，网关支持失败重试及管理端重发通知。首版是否接受“回调驱动自动入账，漏回调等待重试／重发”的能力边界，以及迟到款、退款、计价与网络经营政策，进入下一轮确认。

## 第四轮决策（用户已确认）

- Q11：用户选择“可以，签名回调自动入账，漏通知重试或重发”。合法签名成功通知经商户、原订单、上游交易、金额与资产校验后自动幂等履约；漏通知等待网关重试或运营重发，不使用公开状态独立加钱，不承诺无通知的全自动补单。
- Q12：用户选择“只在宽限期内自动入账，超过后人工核对”，**未接受无限期恢复自动入账的推荐**。USDT 取消与超时都须遵守同一宽限边界；精确时长、计时基准与人工核对入口待下一轮确认。其他既有支付服务商不改。
- Q13：用户选择“可以，不开放自动退款，退款转人工处理”。不新增钱包或自动转账，USDT 禁止通过后台开关或直接 API 绕过该能力限制。
- Q14：用户选择“可以，USD 计价，独立配置倍率和手续费”。USDT 采用 USD 订单计价、独立经营规则，首版默认不叠加现有充值赠送阶梯。网关负责 USD 与实付 USDT 的换算，本站不重复换算，也不把两种资产数量强设相等。
- Q15：用户选择“首版同时开放多个网络供用户选择”，未接受单网络推荐。补充协议核查确认网关收银台仍能切换资产／网络，可能创建子单，商户通常收到父单回调，回调没有 network。订单只能保存 `requested_network`，不能声称 `settled_network` 已被证明；如果网络一致性是硬要求，必须由网关禁用切换、补充回调字段或在真实链路验证后再启用网络敏感自动入账。

用户尚未确认整体方案完备，业务实现与部署仍未开始。

## 第五轮决策（用户已确认）

- Q16：用户选择“可以，默认 30 分钟，后台可改”。USDT 入账宽限期从订单付款有效期结束／用户取消时刻的较早者起算；每张订单固定截止点，重发通知或未来修改配置不能延长已创建订单。
- Q17：用户选择“可以，各网络共享本站倍率与手续费”。USDT 多网络共享 USD 计价、本站充值到账倍率和本站手续费；实际网关报价与链上转账费用不混入本站倍率。
- Q18：用户选择“可以，后台增加待核对与确认处理入口”。增加待人工核对筛选和带备注的处理记录。只有签名、商户、订单和金额均通过、仅超过宽限的款项可人工确认按原单额度入账；不能输入任意补账金额，必须防止重复确认。
- Q19：用户选择“可以，外部购卡使用独立开关”。内置支付关闭后，外部购卡仍可独立启用；新开关默认关闭，未启用时保持现有显示。路由、侧栏和后端读取不能仍硬依赖 `payment_enabled`，且此例外不意外开放内置创建订单接口。

多网络切换与回调父子交易绑定的只读核查已返回；结果已写入 `gmpay-protocol-evidence.md`。

## 验收问题清单（不是已通过的测试）

- 管理后台保存、刷新、重新登录后读回同一配置；普通用户不能读到商户密钥。
- 外部页面入口、暗色／移动端样式、受限 iframe 与新窗口备用入口在真实浏览器可用。
- 外部买卡：以本站余额码兑换成功为入账依据，不以外部付款页事件或前端“支付成功”消息加余额；验证说明、兑换入口与运营提供的卡密适用系统。
- USDT：通过约定服务端回调或可信查询核实收款与到账，不以前端支付结果页作为结算证据。
- USDT 创建订单、签名回调、金额和商户匹配、重复回调、过期与恢复、配置变更后的旧订单行为均有证据。
- 现有支付宝／微信／Stripe／Airwallex、订阅、充值赠送与安全补丁不回退。
- 构建产物身份、自动化测试、独立审查、部署回读、真实付款闭环分别验收；不能互相替代。
