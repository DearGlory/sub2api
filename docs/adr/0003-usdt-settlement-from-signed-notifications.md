# USDT 以签名收款通知入账，公开状态查询不单独触发补账

用户在第四轮访谈接受以下首版能力边界：成功收款通知通过签名、原商户、原订单、上游交易、金额和付款资产校验后，沿用本站订单体系幂等入账；通知未到达时等待网关重试，或由运营在网关管理端重发通知。不要求首版在完全缺失通知的情况下，通过公开状态接口独立完成自动补账。

官方固定版本的公开状态接口只提供交易号与状态，没有目标自动补单所需的金额及订单归属信息。收银台初始化接口用于展示，不因把其字段与状态接口拼接就自动获得完整收款证明。本站不会用本地应收金额填充所谓上游实收金额，也不会引入网关管理员凭据来冒充商户查询协议。

这一取舍使首版保持对官方商户协议的兼容和最小权限，代价是漏通知的自动恢复依赖网关重试，最终需要运营重发或人工核对。前端回跳、页面消息和状态查询都不能直接增加余额；如果回调已到达而本站履约失败，应继续保留并重试同一订单，避免要求用户重新付款。

用户明确选择迟到款只在宽限期内自动入账，超出后人工核对；没有接受无限期恢复。宽限时长、计时基准与人工确认方式待后续轮次确认，不在这里伪造已接受的数值。

USDT 不开放系统自动退款或自助退款；退款由运营在系统外核对处理。本 ADR 不批准私钥托管、自动转账或网关部署。新增 USDT 经营规则与多个可选网络另见最终设计契约，既有支付服务商行为不因此改变。
