# 外部买卡与本站余额兑换分离，不向店铺传递登录身份

用户指定的外部店铺商品说明采用“付款自动发卡密，回指定站点兑换”的模式。第三轮访谈已确认以“店铺购买 → 获得兑换码 → 返回 Sub2API 兑换余额”作为本次外部页面入口的闭环，而不是建设外部支付回调直接入账集成。

因此外部店铺只作为可配置的购买页面，默认嵌入并保留新窗口入口；本站提供兑换指引与现有兑换入口。该入口不向店铺传本站登录 JWT、用户 ID 或完整本站页面地址，也不将 iframe 加载完成、跳转或外部页面消息当作余额入账依据。入账发生在本站成功兑换目标系统的余额码时。

这是明确的业务边界，而不只是展示层简化：它避免给第三方店铺授予本站用户会话或管理入账权限，代价是用户需完成兑换步骤。未选择“向外部收银台透传登录身份并由其调用 Admin API 入账”，不为该入口新增短期身份交换协议；现有通用自定义页面的协议也不因本功能而改动。

运营必须确保店铺实际出售 Sub2API 可兑换的余额码。公开商品当前的原站地址与兑换说明不能证明这一点，本次未修改店铺商品或库存，也未购买或兑换验证。商品适用系统的核对是启用入口前的运营前置条件。

USDT 仍走独立的内置充值订单与网关回调链路；该决定不适用于 USDT 收款确认。两条流程不共享“支付成功即到账”的前端假设。
