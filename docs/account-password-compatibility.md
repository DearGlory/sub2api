# 账户密码兼容与可选密码副本

适用候选版本：`0.2.17-GloryCode-0.0.9`。从管理员指定的 `0.2.17-GloryCode-0.0.7` 开发，并保留期间已发布的 `0.0.8` 支付修复。密码补丁的直接父提交为 `a3b7b221164bf50815e9887fbc3bc0c6ef341eac`；0.0.8 自带的支付迁移 247/248 保留，密码功能本身不新增数据库迁移。

## 账户密码

- 新注册、初始化、用户改密、管理员改密、邮箱重置以及账户创建复用统一账户密码编码器，新写入为 Argon2id。
- 现有 bcrypt 记录由原生 bcrypt 校验器验证，保留其原有格式与成本兼容性。已迁入的 GloryCode Argon2id 参数为 `v=19,m=19456,t=2,p=1`，盐 16 字节、结果 32 字节。
- 登录不会自动改写旧哈希，避免无意改变由邮箱和密码哈希派生的会话版本。
- 仍使用现有 `users.password_hash`，本功能不新增、改名或修改数据库字段、表或迁移。
- 不修改各原生入口的最短密码等规则；编码器有 1 MiB 的资源上限，超限直接拒绝。Argon2id 参数在计算前严格校验，不接受任意放大的参数。
- 不修改 API key、上游账户凭据、支付密钥或 MFA 备用码的存储方式。

## 明文副本配置

这是管理员明确要求的高风险可选功能：副本确实保存可读密码。目录权限不能防止应用账号、root 或备份权限被攻破后泄露密码。

```yaml
password_copy:
  enabled: true
  directory: "./data/password-copies"
```

- **默认开启**。`PASSWORD_COPY_ENABLED=false` 明确关闭；`PASSWORD_COPY_DIRECTORY` 可指定独立目录。修改配置后按应用原有配置加载机制重启生效，不是管理界面的即时热开关。
- 相对路径以应用工作目录解析成绝对路径。标准容器工作目录 `/app` 下默认落在 `/app/data/password-copies`；本地运行应明确设置测试目录，避免混用真实数据目录。
- 显式关闭时不初始化目录、不暂存 MFA 密码材料、不写新副本。关闭不等于删除此前副本；存量文件和备份保留由管理员独立管理。
- Linux 原生实现要求目录归应用运行用户所有、权限 `0700`；记录为 `0600` 普通文件、单硬链接。拒绝符号链接和不安全权限，不自动把不安全的现有文件修成可写。
- 使用目录文件描述符操作、跨实例文件锁、临时文件、原子替换和 fsync。每个数字用户 ID 只保留一份最新成功登录副本，不追加密码历史。
- Windows/macOS 编译保留，但启用副本会明确拒绝该平台；关闭时为无副作用操作。不能把跨平台编译通过理解成非 Linux 副本已实现。

## 写入边界

只在账户密码验证、用户状态与后端模式检查、必要的二步验证及最终访问令牌签发均成功后，HTTP 成功响应写出前保存。以下情况不创建用户副本：错误密码、禁用用户、后端模式拒绝、未完成/失败/过期二步验证、单纯 OAuth/Passkey 登录、令牌刷新和最终令牌签发失败。

MFA 两步之间使用既有服务端临时 session 保存 AES-GCM 加密材料，绑定用户、临时 session、期限与当前密码哈希指纹。Redis 中不是明文密码；成功流程使用原子 GETDEL 消费临时 session。保存副本前复核当前密码；改密后的旧材料不用于副本。

副本是**最近一次成功密码登录时输入的密码**。用户改密、重置密码或只用 OAuth 登录后，副本可能过时，直到下次成功密码登录。副本不得被用于绕过原生认证，也不保证未来任意系统可以无条件迁移。

## 故障与访问

- 初始化、临时材料或写入失败只输出固定事件及必要用户 ID，不打印密码、哈希、加密材料、底层错误或文件内容。
- 可选副本失败不使原本失败的认证成功，也不因归档故障改变已通过认证的登录结果；管理员须监控 `password_copy_store_unavailable`、`password_copy_handoff_unavailable`、`password_copy_handoff_rejected`、`password_copy_save_failed`。
- 不提供读取、导出、搜索副本的 HTTP API；副本不出现在用户表、返回 JSON、普通日志或源代码中。备份规则必须将该目录视为真实凭据。
- 首次运行遇到目录创建失败时会告警并保持本次进程的副本存储不可用；修复路径权限后需重新启动应用加载。

## 发布边界

该候选仅进行本地实现、测试和提交；生产部署、数据装载及 Nginx 切换不是本阶段已完成事项。密码哈希属于兼容存储，不应再采用临时“登录后转回 bcrypt”的旧设计。历史充值与请求数据继续按已批准方案外部存档。
